## Согласованное оформление

Описание Linear противоречит живому макету в подписях и состоянии рун.
Пользователь явно выбрал **«Точно как Figma: „Осталось“, руны с замком»**.

Числа ниже — состояние примера в Figma, а не фиксированные значения для пользователей.

| Карточка | Выполнено | Всего | Подпись | Заполнено сегментов | Состояние |
| --- | ---: | ---: | --- | ---: | --- |
| Раскинуть карты Таро | 2 | 5 | Осталось 3 из 5 | 2 | Обычное |
| Открыть гороскоп | 2 | 3 | Осталось 1 из 3 | 2 | Обычное |
| Открыть руны | 0 | 3 | Осталось 3 из 3 | 0 | Размытие и замок |

Остаток и заполнение вычисляются из одного `completedCount`; значение ограничено диапазоном 0…totalCount. Английская подпись: `3 of 5 remaining`. Замок и размытие вычисляются в самой карточке: при нулевом прогрессе они показаны, после первого действия снимаются. Правило одинаковое для всех трёх достижений.

Экран читает `UserProvider.currentUser.statistics` из серверного профиля и реагирует на обновления и смену аккаунта. Подписи и сегменты вычисляются из этих счётчиков, значения Figma используются только в тестовой фикстуре. Старые профили без статистики получают нулевые значения. Все три карточки показывают замок при нулевом счётчике. Обычный PATCH профиля не отправляет статистику, чтобы не перезаписать новый прогресс устаревшим снимком. Баланс и PRO берутся из `MonetizationProvider`.

## Согласованное правило зачёта и сохранение

Пользователь подтвердил восстановление правила из старой реализации `854a0f9` (`origin/dev/new-backend`):

- Таро: +1 за открытие карты дня, цель 5.
- Руны: +1 за открытие руны дня, цель 3.
- Гороскоп: +1 за новый успешно полученный прогноз, цель 3.
- Повторный просмотр того же результата не даёт дополнительного прогресса.

Ключи повторного зачёта: UID + тип действия + дата символа дня; для гороскопа — UID + тип прогноза (day/week/month/year) + календарная дата окончания прогноза. Один дневной символ засчитывается один раз в день; смена языка или повторное открытие не добавляют очков. Полоса ограничена целью, серверный счётчик продолжает хранить число действий. У каждой карточки замок снимается после её первого зачтённого действия независимо от остальных достижений.

`POST /api/v1/users/me/achievement-events` принимает `kind` и `reference`, определяет UID по сессии и атомарно сохраняет ключ события вместе с увеличением `users.statistics`. Статистика и служебные ключи защищены от обычного PATCH/complete-profile. Платные гороскопы дополнительно засчитываются в транзакции серверного сохранения результата: потеря ответа клиентом не теряет достижение, последующий клиентский запрос с тем же ключом не удваивает его.

Приложение сохраняет события в отдельной Hive-очереди до отправки. Неуспешные запросы повторяются при следующем действии, возвращении приложения на экран или входе в аккаунт. Очередь разделена по UID; запоздалый ответ не применяется к другому аккаунту. Обновление счётчиков не подтверждает другие несохранённые изменения профиля. В пределах запущенного приложения устаревший снимок профиля не уменьшает уже подтверждённый прогресс.

Открытое состояние карты/руны привязано к календарной дате, поэтому после полуночи новый символ не наследует вчерашний флаг. Исторические действия, которые раньше не записывались, автоматически не реконструируются; существующие сохранённые счётчики сохраняются.

Порядок выпуска: сначала обновить `asteria-back` и проверить `/health/ready`, затем собрать и запустить обновлённый `asteria-app`. Сам факт push не подтверждает успешное развёртывание; проверять результат workflow и запущенную версию отдельно.

В Flutter поверхность рисуется существующим `StaticGlassSurface`, фон — `StaticGlassBackdrop`. Это принятая в приложении реализация стекла, а не растровый снимок карточки. Нативная шапка сохраняет состояние PRO пользователя.

В обычном масштабе карточки имеют высоту 128. На узком экране или при увеличении системного текста карточки растут по содержимому, заголовки переносятся без многоточия, шапка переносит баланс и PRO на отдельную строку. Экран прокручивается.
