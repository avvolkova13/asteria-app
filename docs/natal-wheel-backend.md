# Границы домов для купленной натальной карты

После покупки Flutter рисует круг «Мягкий рельеф» из данных рождения. Для расположения планет он читает долготы из `positions`, для нитей между планетами вычисляет углы между ними. Для отображения 12 домов Плацидуса нужны их индивидуальные границы. Номер дома у планеты и текстовый `house_summary` этих границ не задают.

Контрольный запрос к действующему API на 12 ноября 2026 года: 3 февраля 2001 года, 12:34, широта 51,5°, долгота −0,12°. Получены 19 позиций, система Placidus, зодиак Tropical. Поля с 12 границами в ответе нет. Это искусственный пример для воспроизведения.

## Что изменить на сервере

1. В существующий ответ `POST /api/v1/planets_houses_position` добавить необязательное поле верхнего уровня `house_cusps`. При успешном расчёте это массив из 12 объектов в порядке домов I–XII. У каждого объекта два поля: `house` — целое от 1 до 12, `longitude` — числовая эклиптическая долгота начала этого дома в градусах от 0 включительно до 360 исключительно. Пример одного элемента: `{"house": 1, "longitude": 85.428608}`. Ноль — полноценная координата.
2. Взять границы из того же расчёта, что и существующие положения планет, ASC и MC. Использовать те же место, переведённый в UTC момент рождения, зодиак и систему домов. Сохранить точность исходных чисел. Если движок не смог посчитать запрошенную систему, вернуть `null` или опустить массив и сохранить доступные позиции планет. Подмена равными секторами исказит рисунок.
3. Проверить сохранение вложенных данных профиля. При записи и последующем чтении `planets_houses_data.house_cusps` должен возвращаться без потерь, как и `personal_info.birth_date.birth_time_known`. Последний флаг клиент уже отправляет при регистрации: `true` — введено точное время, в том числе ровно полночь или полдень, `false` — человек выбрал приблизительное время или указал, что не знает его. Старое отсутствие флага допустимо. Если профиль уже сохраняет оба поля как произвольный JSON, достаточно подтвердить это тестом.
4. Сохранить существующий контракт покупки. Обычное открытие уже купленной карты может повторить запрос геометрии со старыми параметрами. Этот запрос должен оставаться доступен без повторной оплаты и без повторной генерации текстов. Приблизительность известна клиенту из профиля: в текущем запросе расчёта передаются числовые час и минута. По ним одним нельзя определить, знает ли человек время.

## Как принять

- Для тестового профиля с точным временем сверить все 12 границ с результатом движка. Для Плацидуса начало I дома совпадает с ASC, X дома — с MC, с учётом точности исходных значений. Обход по номерам делает один полный оборот через 0°. Все 12 номеров уникальны.
- Повторить для другого времени или места рождения и сверить именно его границы. Проверить переход через 0°, отсутствие результата на неподдерживаемой широте и чтение старого ответа без нового поля.
- На тестовом аккаунте купить карту, закрыть и открыть снова. При наличии границ и точного времени видны границы домов; повторное открытие не меняет баланс. Открыть ранее купленную карту без сохранённых границ и убедиться, что они догружаются, а прежний разбор остаётся на месте.
- Проверить сохранение флага точности на сервере отдельно для точной полуночи и неизвестного времени. На телефоне первое значение допускает показ домов, второе оставляет только приблизительное положение планет.
- Приложить к задаче обезличенный JSON успешного ответа и пример ответа без границ. Flutter уже принимает эти варианты.
